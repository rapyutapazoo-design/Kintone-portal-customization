# テンプレートフォルダ

このフォルダには、リポジトリ本体（適用ファイル・実値入り）から**固有情報をプレースホルダーに置き換えたテンプレート**が入っています。他の組織でこのカスタマイズを流用する場合は、このフォルダの内容をベースにしてください。

---

## 📂 このフォルダの位置づけ

- 実際のアプリID・組織コード・グループコードなど**固有情報を含む実値ファイルは、本リポジトリには置きません**（動作確認は各機能の開発プロジェクト側・非公開で行います）。
- **`テンプレートフォルダ/`（このフォルダ）** ＝ 本リポジトリで公開する唯一の配布物です。実値はすべてプレースホルダーに置き換わっています。

このフォルダは自動生成ではなく、**直接編集して保守**してください（`scripts/generate-template.js` は現在対象なし。実値ファイルからの自動生成が必要な機能が今後増えた場合のための土台として残しています）。

> **📝 変更履歴**
> - フォルダ名を `ショトカボタン` → `ショートカットボタン` に改名しました。あわせて `portal-shortcut.js` の ⚙️ 設定モーダルのデザインを刷新しています（詳細は下記）。
> - **公開対象をこのフォルダ直下のみに一本化**しました。従来リポジトリ直下にあった `スペース設定/` `フォントサイズ/` `ホームボタン/` `問い合わせボタン/` をこのフォルダへ移行し（実値を含むものはプレースホルダー化）、直下からは削除しています。
> - プロフィール閲覧制限のKintoneプラグイン一式・お問い合わせボタンの告知画像は、実装詳細・掲示物のため引き続き公開の対象外です。

## 🔧 含まれるファイルとプレースホルダー

### `ショートカットボタン/portal-shortcut.js`

`appList`（ポータルに配置するアプリの一覧）が以下のプレースホルダーになっています。

```js
var appList = [
    { id: 'your-app-id-1', name: '管理規約' },   // 実IDは非公開の実値版ファイルに記入
    { id: 'your-app-id-2', name: '意見書' },     // 実IDは非公開の実値版ファイルに記入
    { id: 'your-app-id-3', name: '施設予約' },   // 実IDは非公開の実値版ファイルに記入
    { id: 'your-app-id-4', name: 'カレンダー' }  // 実IDは非公開の実値版ファイルに記入
];
```

- `your-app-id-N` … 実際に配置したいKintoneアプリの**アプリID**（数値）に書き換えてください。本テンプレートでは表示名（管理規約／意見書／施設予約／カレンダー）のみ実際の運用値に更新済みで、アプリIDは本リポジトリがパブリックのためプレースホルダーのまま維持しています。実IDは非公開の実値版ファイル（各機能の開発プロジェクト側）にのみ記入してください。
- `name` … ポータルに表示する**ボタンの表示名**（絵文字を含めても構いません）です。
- 配置するアプリの数に応じて、行を自由に増減できます。
- この `appList` は**ユーザーが ⚙️ ボタンで個人設定を行っていない場合に表示される既定値**です。既定値の変更は、これまでどおりこのファイルを書き換えて再配置する運用（自動化はしていません）です。

#### ⚙️ 個人カスタマイズ機能について

ポータル上部の 🎨（色変更）・🔲（形変更）に加えて、⚙️ ボタンからユーザー本人がショートカットの**遷移先（アプリ／スペース）・表示名・並び順・個数（4〜6個）**を編集できます。各行は「登録する遷移先」「ボタンに表示する名前」のラベル付きカードとして表示され、モーダル冒頭に簡単な説明文が表示されます。

- 遷移先は**名前順に並んだ選択肢（プルダウン）から選ぶ方式**です。IDは画面に表示されません。選択肢は「アプリ」「スペース」の2つの `<optgroup>` に分かれて表示され、1つの選択欄でどちらも選べます。アプリの選択肢には、そのユーザーが閲覧できるアプリのみが並びます。
- **スペースの候補**は、既に配置されているアプリの所属スペース（`/k/v1/apps.json` の `spaceId`）から自動的に集められます。アプリを1つも持たないスペースは自動収集の対象外のため一覧に出ません。その場合はモーダル内の「一覧に無いスペースを追加」欄に、スペースのURL（`/k/#/space/16` など）または数字のスペースIDを貼り付けて「候補に追加」を押すことで、候補へ追加できます。存在しない・閲覧権限が無いスペースを指定した場合は入力欄の近くに赤字でエラーが表示されます。スペース名の取得に失敗しても、アプリの候補だけでモーダルは正常に開きます。
- 表示名は既定で選択した名称に追従し、任意に上書きできます（未入力の場合は選択した名称がそのまま表示されます）。
- 編集中の内容は**「完成イメージ」としてプレビュー表示**されます。テーマ色（🎨）と角丸（🔲）は実際のボタンと同じ値が使われるため、保存前に見え方を確認できます。スペースを選んだ行はプレビューの先頭に 📁 が付きます。未選択の行は「未選択」と表示されます。
- モーダルの配色は**🎨 で選択中のテーマカラーに連動**します。テーマを切り替えたあとにモーダルを開くと、新しい配色で表示されます。
- 設定はブラウザの `localStorage`（キー: `kintone_portal_shortcuts_<ログインユーザーID>`。ユーザーIDが取得できない場合のフォールバックキー: `kintone_portal_shortcuts_default`）に**キャッシュ**として保存され、ポータル描画は常にこのキャッシュから即時に行われます。
- 保存データが存在しない・壊れている・件数が4〜6個の範囲外などの場合は、常に既定の `appList` へ自動フォールバックします（ポータルが空表示になることはありません）。
- アプリ一覧の取得（Kintone REST API `/k/v1/apps.json`）は ⚙️ モーダルを開いたときのみ行われ、通常のポータル表示時には実行されません。

#### 🔄 端末間同期（任意・設定アプリ方式）

既定では、⚙️ モーダルで編集した設定は**「すべての端末で共有する」**が選ばれており、別途用意した「設定アプリ」経由で PC・スマホ・他ブラウザ間でも同じショートカットが表示されます。ユーザーは⚙️モーダル内の「この設定の保存先」ラジオで、いつでも**「この端末だけに保存する」**（従来どおり localStorage のみ・同期しない）に切り替えられます。

**設定アプリの作り方**

1. Kintone上に新規アプリを1つ作成します（名称は任意。例:「ポータルショートカット設定」）。
2. 以下の2フィールドのみを作成します。

   | フィールドコード | 種類 | 設定 |
   |---|---|---|
   | `login_name` | 文字列（1行） | 重複禁止（Unique）を有効にする |
   | `settings_json` | 文字列（複数行） | 特になし |

3. レコードのアクセス権限を「**作成者のみ**閲覧・編集・削除できる」に設定します（他人の設定を取得・変更できないようにするため）。
4. 作成したアプリのアプリIDを確認し、`portal-shortcut.js` 内の `SETTINGS_APP_ID`（プレースホルダー: `your-settings-app-id`）を実際のアプリIDに書き換えます。

**同期が無効化される場合**

`SETTINGS_APP_ID` がプレースホルダー（`your-settings-app-id`）のままの場合、同期機能一式が自動的に無効化されます。この場合:

- ⚙️ モーダルに保存先ラジオ自体が表示されません。
- 設定アプリへのリモートAPI（GET/POST/PUT/DELETE）は一切呼ばれません。
- 保存先は常に「この端末だけに保存する」として扱われ、従来どおり端末（ブラウザ）ごとの `localStorage` のみで動作します。

**保存先モードの保存場所**

「すべての端末で共有する／この端末だけに保存する」の選択自体は、端末ごとの `localStorage`（キー: `kintone_portal_shortcuts_mode_<ログインユーザーID>`）に保存されます（同期のON/OFFという選択は端末固有の情報のため、設定アプリのレコードには保存しません）。

**設定データのスキーマ（v2）**

`localStorage` および設定アプリの `settings_json` に保存される JSON は、スペース対応にあわせて **v2**（`{ version: 2, buttons: [{ type, targetId, targetName, label, labelCustom }] }`）になっています。`type` は `'app'` または `'space'` です。

- 旧 **v1**（`{ version: 1, buttons: [{ appId, ... }] }`）のデータは、**読み込み時に自動的に v2（`type: 'app'`）へ移行**されるため、既存ユーザーの設定はそのまま引き継がれます。移行後に保存すると v2 で上書きされます。
- 注意: JS を更新する前のブラウザキャッシュが残った端末が v2 のデータを読むと、スキーマ不明として**既定の `appList` 表示に一時的に戻ります**（データは壊れません。JS が更新されれば元に戻ります）。展開直後は、各端末で一度スーパーリロードしてもらうと確実です。

### `スペース設定/space-visibility-filter.js`

表示対象スペースIDが以下のプレースホルダーになっています。

```js
VISIBLE_SPACE_IDS: ['your-space-id-1', 'your-space-id-2', 'your-space-id-3', 'your-space-id-4'],
```

- `your-space-id-N` … ポータルに表示し続けたい**公開スペースのID**に書き換えてください。ここに無い未参加の公開スペースはポータルから隠されます。
- コメント中の ID と名称の対応表（`//   your-space-id-1 = スペース名1 / ...`）も、実際の運用に合わせて書き換えてください。
- `ALWAYS_KEEP_SPACE_IDS`（既定は空配列）は、鍵マークによる自動判定が壊れた場合の保険用です。詳細は [`スペース設定/space-visibility-filter-README.md`](スペース設定/space-visibility-filter-README.md) を参照してください。

### `問い合わせボタン/inquiry-button.js`

お問い合わせ先アプリのIDが以下のプレースホルダーになっています。

```js
var INQUIRY_APP_ID = 'your-inquiry-app-id';
```

- `your-inquiry-app-id` … お問い合わせを受け付ける**Kintoneアプリのアプリ ID**に書き換えてください。
- 告知画像（`inquiry-button-announcement.png`）は掲示物のため本テンプレートには含めていません。導入時は任意でご自身の告知画像をご用意ください。

### `プロフィール閲覧制限/プロフィール閲覧制限カスタマイズ/config.js`

プロフィール閲覧を許可する組織・グループが以下のプレースホルダーになっています。

```js
allowedOrgs: ['YOUR_ORG_CODE'],
allowedGroups: ['YOUR_GROUP_CODE'],
```

- `YOUR_ORG_CODE` … 閲覧を許可する**組織のコードまたは名前**に書き換えてください。
- `YOUR_GROUP_CODE` … 閲覧を許可する**グループのコードまたは名前**に書き換えてください。
- 複数指定する場合は配列にカンマ区切りで追加できます（例: `['YOUR_ORG_CODE_1', 'YOUR_ORG_CODE_2']`）。

`main.js`・`restriction.css` は固有情報を含まないため、無変更でそのまま利用できます。

## ⚙️ 導入方法

1. このフォルダの各ファイルをコピーし、上記のプレースホルダーを実際の値に書き換えます。
2. Kintoneのシステム管理から「JavaScript / CSS でカスタマイズ」を開き、書き換えたファイルを登録します。
3. リポジトリ本体（`Kintone全体カスタマイズ`）の各READMEに記載の導入手順・注意事項もあわせてご確認ください。
