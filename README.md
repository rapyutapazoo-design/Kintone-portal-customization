# Kintone 全体カスタマイズ

Kintone に登録している全カスタマイズファイル（JavaScript / CSS）を**一元管理する**リポジトリです。
機能カテゴリごとにフォルダを分け、引き継ぎ・運用保守をしやすくすることを目的としています。

---

## 📂 ファイル構成

```text
Kintone全体カスタマイズ/               ← 親（リポジトリルート・パブリック公開）
├── README.md                        ← 本ファイル（導入・運用手順）
├── .gitignore                       ← 本番用フォルダ/ を管理対象外にしている
├── scripts/
│   └── generate-template.js          ← 本番用フォルダ → テンプレートフォルダ の自動生成スクリプト
├── 本番用フォルダ/                    ← 【Git管理対象外】実値入り。Kintoneへ登録するのはこちら
│   ├── ショートカットボタン/
│   ├── スペース設定/
│   ├── フォントサイズ/
│   ├── ホームボタン/
│   ├── プロフィール閲覧制限/
│   ├── モバイル版画像表示/
│   └── 問い合わせボタン/
└── テンプレートフォルダ/               ← 【公開用・生成物】プレースホルダー版
    ├── README.md                     ← プレースホルダーの説明・埋め方（テンプレート専用）
    └── （本番用フォルダと同じ構成）
```

**本番用フォルダとテンプレートフォルダは同一のファイル構成**で、違いは中身の値だけです。本番用には実際のアプリID・スペースID・名称が入り、テンプレート用にはプレースホルダーが入ります。

### 🔐 運用フロー（パブリックリポジトリのため）

本リポジトリは**パブリック**です。実際のアプリID・スペースID・組織名などの**固有情報を公開しない**ため、次の流れで運用します。

```text
1. 本番用フォルダ/ を編集       ← 実値入り。ここだけが編集対象
2. Kintone へ登録して動作確認   ← 実機での確認
3. node scripts/generate-template.js  ← テンプレートを自動生成＋実値スキャン
4. 差分を確認してコミット・プッシュ    ← 公開されるのはテンプレート側のみ
```

| フォルダ | Git | 中身 | 編集 |
|---|---|---|---|
| `本番用フォルダ/` | **管理対象外**（.gitignore） | 実際のID・名称 | ✅ ここを編集する |
| `テンプレートフォルダ/` | 追跡（公開される） | プレースホルダー | ❌ 生成物。直接編集しても次回生成で上書きされる |

#### generate-template.js の安全装置

生成後、全ファイルを走査して**置換ルールから漏れた実値を検出したらエラー終了**します。人が気づかなくても公開事故を止める仕組みです。実値を持つファイルを新しく追加した場合は、`REPLACEMENTS` に置換ルールを追加してください（追加しないと生成が失敗するため、書き漏れに気づけます）。

現在、実値を持つファイルは次の3つです。

| ファイル | 含まれる実値 |
|---|---|
| `ショートカットボタン/portal-shortcut.js` | ショートカットのアプリID4件・設定アプリID |
| `問い合わせボタン/inquiry-button.js` | お問い合わせアプリID |
| `スペース設定/space-visibility-filter.js` | 表示対象スペースID・スペース名 |

#### テンプレートに含めないもの

`plugin.zip`（ビルド成果物）、`*.ppk`（Chrome拡張の秘密鍵）、`.DS_Store`、`node_modules/`、`scripts/` は生成時に除外されます。

## 🚀 ショートカットボタン（`テンプレートフォルダ/ショートカットボタン/portal-shortcut.js`）

Kintone ポータル画面の上部に、よく使うアプリへのショートカットボタンを配置します。

- **アプリショートカットボタン**
  - `appList` 配列（`portal-shortcut.js` 内）は**未設定時に表示される既定値**です。配置したいアプリのIDと表示名を列挙します。プレースホルダー（`your-app-id-1` 等）を実際のアプリIDに書き換えて利用してください。詳細は [`テンプレートフォルダ/README.md`](テンプレートフォルダ/README.md) を参照。
  - ボタンの遷移先は各アプリの `/k/{アプリID}/` です。行数は自由に増減できます（既定値としては4〜6個程度が目安）。
- **カラーテーマ変更（🎨）・形状変更（🔲）**
  - ボタンのグラデーション配色（navy / green / purple / standard）と角丸形状（capsule / rounded）を切り替えできます。
  - 選択値はブラウザの `localStorage`（`kintone_portal_theme_idx` / `kintone_portal_shape_idx`）に個別保存されます。
- **個人カスタマイズ（⚙️）**
  - 🎨・🔲 の隣の ⚙️ ボタンから、ショートカットの**遷移先アプリ・表示名・並び順・個数（4〜6個）**をユーザー本人が編集できるモーダルを開きます。各行には「登録するアプリ」「ボタンに表示する名前」のラベルが常時表示され、カード状にまとまった行に番号が振られます。
  - アプリはアプリ名順に並んだ選択肢（プルダウン）から選びます（アプリIDは画面に表示されません）。表示名は既定でアプリ名に追従し、任意に上書きできます（未入力の場合はアプリ名がそのまま表示されます）。
  - 編集中の内容は**「完成イメージ」としてモーダル内にプレビュー表示**され、保存前にポータル上での見え方を確認できます。
  - モーダルの配色は**🎨 で選択中のテーマカラーに連動**します（ヘッダー・保存ボタン・フォーカス色などがテーマに追従）。
  - 設定はブラウザの `localStorage`（`kintone_portal_shortcuts_<ログインユーザーID>`）に**ログインユーザー単位**でキャッシュされ、常にこのキャッシュから即時に描画されます。未設定・保存データが壊れている・件数が範囲外などの場合は、常に既定の `appList` へ自動的にフォールバックし、ポータルが空になることはありません。「既定に戻す」ボタンで保存内容を削除し、いつでも既定値に戻せます。
  - アプリ一覧の取得（`/k/v1/apps.json`）は ⚙️ モーダルを開いたときのみ実行され、通常のポータル表示時には行われません。
- **端末間同期（任意・設定アプリ方式）**
  - 別途用意した「設定アプリ」を使うことで、⚙️ モーダルの「この設定の保存先」ラジオから**「すべての端末で共有する（既定）」／「この端末だけに保存する」**をユーザー自身が選べます。共有を選んだ場合、保存内容は設定アプリのレコード（自分の分のみ）に保存され、他端末・他ブラウザでも同じ内容が反映されます。
  - 保存先の選択自体は端末ごとの localStorage（キー: `kintone_portal_shortcuts_mode_<ログインユーザーID>`）に保存されます。
  - ポータル描画は常に localStorage キャッシュから即時に行われ、共有モードのときだけ描画直後に非同期でリモート設定と照合し、内容が異なる場合のみキャッシュを更新して再描画します（初期表示速度への影響なし）。取得失敗時やレコードなしの場合は何もせず、キャッシュ表示を維持します。
  - 共有モードでの保存は、設定アプリへの保存が成功してからローカルキャッシュを更新します。失敗した場合はモーダルを閉じずにエラーを表示します。共有モードでの「既定に戻す」は、設定アプリのレコードを削除できてからローカルキャッシュを削除します（すべての端末の設定が既定に戻ります）。
  - `portal-shortcut.js` 内の `SETTINGS_APP_ID` がプレースホルダー（`your-settings-app-id`）のままの場合、同期機能自体が無効になり、保存先ラジオも表示されず、リモートAPIも一切呼ばれません。従来どおり端末（ブラウザ）ごとの保存のみで動作します。設定アプリの作り方・書き換え方法は [`テンプレートフォルダ/README.md`](テンプレートフォルダ/README.md) を参照してください。

### 🧩 共有コーディネーター `window.PortalCustomize`

ポータル上部のコンテナと「マウントスロット」を提供する軽量な共有ロジックです。各機能ファイルは「自分のボタンを所定スロットに挿す」ことだけに責務を限定でき、**読み込み順に依存せず**に協調動作します。

- **冪等初期化**: コンテナは一度だけ生成されます（重複防止 ID: `my-custom-app-container`）。
- **提供スロット**:
  - スロット1: ショートカットボタン群 … `addShortcutItem(el)`
  - スロット2: 色 / 形ボタン … `addConfigItem(el)`
  - スロット3: フォントボタン群（`configContainer` 右寄せ）… 本リポジトリでは未使用。将来フォント機能を分割した際に `getConfigContainer()` を取得してマウントする想定です。

> フォント設定（`localStorage` キー・`kintone-font-size-changed` イベント）はフォント側の所有物であり、`portal-shortcut.js` からは一切操作しません。

## 🏠 ホームボタン（`ホームボタン/mobile-home-button.js`）

**モバイル専用**のカスタマイズです。画面下中央に、モバイルポータル（`/k/m/`）へ戻る丸いボタン（FAB）を表示します。

- 表示対象画面（`kintone.events.on` の登録イベント）:
  - `mobile.app.record.index.show`（レコード一覧）
  - `mobile.app.record.detail.show`（レコード詳細）
  - `mobile.space.portal.show`（スペースのポータル）
- ポータル（ホーム）画面では表示しません（既にホームのため不要）。
- `document.body` に直接追加し、独自 ID `mobile-home-shortcut` で重複生成を防ぎます。他ファイルへの依存はありません。

## 🔠 フォントサイズ変更（`フォントサイズ/font-size-changer.js`）

画面右下に常駐する**格納式セグメントUI**から、文字サイズを「小（14px）/ 中（18px）/ 大（24px）」で切り替えます。

- **格納 / 展開**: 格納時は「**文字**」ボタン、クリックで小中大セグメントが展開します（展開レイアウトは `[小 中 大]`（px併記・スライドインジケータ）＋ 右に「文字」ボタン）。
- **対象画面共通**: ポータル・レコード一覧/詳細・レポート・スペースの各画面（PC / モバイル）で同じUI・操作を提供します。
- **状態の永続化**: 開閉状態は `localStorage`（`kintone-font-ui-collapsed`、既定は格納）、選択サイズは `localStorage`（`kintone-custom-font-size`）に保存し、再読み込み後も維持します。
- **スタイル注入**: ウィジェットの見た目は重複防止ID付きの `<style>`（`kintone-font-ui-style`）で1度だけ注入します。
- **Allowlist方式のCSS注入**: レコード値・コメント・ポップアップ等の「読むテキスト」エリアのみを対象とし、ヘッダー・サイドバー等のシステムUIは除外して表示崩れを防ぎます。スペース・アプリ一覧・通知カードは対象外です。
- **自己完結**: ショートカット機能や共有コーディネーター `window.PortalCustomize` には依存しません。

> 設計上、ポータル上部にインラインの小中大ボタンは持ちません（右下のウィジェットに一本化）。

## 🗂 ポータルのスペース一覧 表示制御（`スペース設定/space-visibility-filter.js`）

ポータルの「スペース」ポートレットから、**ホワイトリストに登録していない公開スペースを非表示**にします。マンションのコミュニティ用スペースを**ハブスペース経由**でアクセスさせるための UI 整理です。

- **ホワイトリスト方式**: `VISIBLE_SPACE_IDS`（既定 `['2', '3', '6', '16']`）に無い公開スペースは自動的に隠れます。新しくコミュニティ用スペースを作っても設定変更は不要です。
- **鍵マーク付き（非公開）スペースは対象外**: Kintone 標準で参加者にしか表示されないため、そのまま残します。
- **参加済みなら表示**: ホワイトリスト外でも、すでに参加しているスペースは表示されます。全ユーザーに同じルールを適用し、管理者等の特別扱いはありません。
- **PC・モバイル共通**: 1 ファイルで両方に対応し、同じファイルを PC 用・スマートフォン用の両方に登録します。
- **フェイルセーフ**: 判定に失敗した場合は「何も隠さない」＝ Kintone 標準の表示に戻ります。スペース一覧が隠れたままになることはありません。

> **セキュリティ機能ではありません。** ポータルの見た目から消えるだけで、URL 直打ち・全体検索からは引き続きアクセスできます（スペースは公開のままで、誰でも自由に参加できます）。

設定方法・鍵マーク判定が壊れた場合の復旧手順は [`スペース設定/space-visibility-filter-README.md`](スペース設定/space-visibility-filter-README.md) を参照してください。

## 🚪 スペースの参加・退会ボタン（`スペース設定/space-join-button.js`）

スペースのトップ画面に「参加する」「退会する」ボタンを表示します。Kintone 標準では参加・退会が右上の「…」メニューの中にしかなく気づけないため、**参加したつもりで参加できていない**という状態が起きます。これを1クリックに集約します。

- **参加状況に応じた3状態**: 非メンバーには「参加する」、自分で参加した明示的メンバーには「退会する」を表示します。
- **暗黙的メンバーにはボタンを出しません**: `everyone` などの組織・グループ経由でメンバーになっている場合、Kintone 自身が参加・退会の手段を持たないため（個人単位で抜けられない）、押しても失敗するボタンを表示しません。
- **自分1人だけを操作**: Kintone 本体と同じ内部エンドポイントを使い、自分の参加・退会だけを行います。メンバー一覧を全件置換する REST API は、同時更新で他の人の変更を消す危険があるため使いません。
- **PC・モバイル共通**: モバイル版 Kintone には参加・退会 UI が標準で存在しないため、両方に同じ方式で提供します。
- **フェイルセーフ**: 状態を判定できない場合はボタンを表示しません。失敗しても Kintone 標準の画面はそのまま使えます。

> コミュニティ用スペースには **`everyone` をメンバーに入れないでください**。入れると全員が暗黙的メンバーになり、参加ボタンが出ず退会もできなくなります。

詳細は [`スペース設定/space-join-button-README.md`](スペース設定/space-join-button-README.md) を参照してください。

## ⚙️ 導入方法

1. `テンプレートフォルダ/` 配下のファイル（`ショートカットボタン/portal-shortcut.js`・`プロフィール閲覧制限/…/config.js` 等）はプレースホルダーを実際の値に書き換えてから利用してください（詳細は [`テンプレートフォルダ/README.md`](テンプレートフォルダ/README.md)）。
2. Kintone のシステム管理から「JavaScript / CSS でカスタマイズ」を開きます。
3. 各ファイルを対象プラットフォームのアップロード欄に登録します。
   - `テンプレートフォルダ/ショートカットボタン/portal-shortcut.js`（書き換え後） → **PC 用の JavaScript ファイル**
   - `ホームボタン/mobile-home-button.js` → **スマートフォン用の JavaScript ファイル**
   - `フォントサイズ/font-size-changer.js` → **PC 用・スマートフォン用の両方の JavaScript ファイル**
   - `スペース設定/space-visibility-filter.js` → **PC 用・スマートフォン用の両方の JavaScript ファイル**
   - `スペース設定/space-join-button.js` → **PC 用・スマートフォン用の両方の JavaScript ファイル**
   - `プロフィール閲覧制限/` ・`モバイル版画像表示/` 配下の登録用ファイルは、それぞれの元プロジェクトの導入手順に従ってください。
4. 設定を保存し、対象画面を再読み込みして動作を確認してください。

> フォント機能を含む旧ファイル（ショートカット＋フォント混在版）を併用している場合は、フォントUIの二重表示を避けるため、旧ファイルを停止してから本ファイルを適用してください。

## ⚠️ 運用・保守上の注意

- **既存ファイルとの同時適用は避けてください。**
  `portal-shortcut.js` は重複防止 ID に既存ファイルと同一の `my-custom-app-container` を使用します。旧来のポータルカスタマイズファイルと**同時に適用すると、先に実行された側のみが描画され、ショートカットの二重表示や色/形ボタンの欠落が発生**します。旧ファイルを置き換えてから適用してください。
- **DOM 操作に関する注意**: Kintone 本体のアップデートにより DOM 構造が変わると、動作に影響が出る可能性があります。
- 本リポジトリには API キー等の機微情報は含めません。
