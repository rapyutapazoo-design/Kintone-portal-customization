# Kintone 全体カスタマイズ

Kintone に登録している全カスタマイズファイル（JavaScript / CSS）を**一元管理する**リポジトリです。
機能カテゴリごとにフォルダを分け、引き継ぎ・運用保守をしやすくすることを目的としています。

---

### 🔐 実値ファイルとテンプレートファイルの関係（パブリックリポジトリのため）

本リポジトリは**パブリック**です。実際のアプリID・スペースID・組織コードなど**固有情報を含むファイルはリポジトリに置きません**。

- `テンプレートフォルダ/` 配下は、実値を含む機能について**プレースホルダー版のみ**を配置しています。
- 実際に動作確認・運用するための**実値入りファイルは、リポジトリ直下の `本番用フォルダ/` で管理**します（`.gitignore` で Git 管理外。ローカルだけに置きます）。
- 変更は**本番用フォルダで先に行い、実機で確かめてから**テンプレートへ反映します。テンプレートとの差は、プレースホルダー行だけに保ちます。
- プロフィール閲覧制限とモバイル版画像表示は、これとは別に、各機能の開発プロジェクト側（非公開）が元になっています（混同しないでください）。
- `テンプレートフォルダ/` 配下は自動生成ではなく**直接編集で保守**します（詳細は [`テンプレートフォルダ/README.md`](テンプレートフォルダ/README.md)）。

## 🧭 ポータルナビ（`テンプレートフォルダ/ポータルナビ/portal-navigation.js`）

`mobile-home-button.js`（ホームボタン）と `portal-shortcut.js`（ショートカット・色/形・個人カスタマイズ・端末間同期）を **1ファイルに統合**し、管理者が全ユーザーの既定値を決められる「全体設定」と「管理者設定画面」を加えたものです。`window.PortalCustomize` や DOM ID（`my-custom-app-container` など）は従来のまま維持しているため、`font-size-changer.js` は無改修で動きます。**PC 用・スマートフォン用の両方に登録**します。

### 概要と優先順位

- 表示の優先順位は **個人設定 → 全体設定 → JS 内の既定値**（`appList`・ネイビー・カプセル・丸）です。
- 管理者が「強制反映」を付けて保存したときだけ、それより前の個人設定を無効にします（ショートカットとデザインを別々に判定）。
  - 全体設定には、保存のたびに +1 される改訂番号 `settingsRev` と、強制反映した時点の番号 `shortcutsForceRev` / `designForceRev` があります。
  - 個人設定には、保存した時点の `settingsRev` を `baseRev` として覚えます。`baseRev` が ForceRev より小さい個人設定は無効です。
- 全体設定はブラウザに最長 **10分** キャッシュされます。管理者が保存した内容は、他の利用者の画面に最長10分以内に反映されます（保存した管理者自身には即時反映）。
- 強制反映の直後でも、キャッシュが古い利用者は最長10分前の改訂番号で個人設定を保存することがあります。その保存は、キャッシュが更新されたときに無効と判定されます（⚙️ を開くたびに全体設定を取り直して、この遅れを小さくしています）。

### 2つの設定アプリの違い（個人設定アプリ／全体設定アプリ）

| 項目 | 個人設定アプリ（`SETTINGS_APP_ID`） | 全体設定アプリ（`GLOBAL_SETTINGS_APP_ID`） |
|---|---|---|
| 目的 | 利用者本人の ⚙️ ショートカットの端末間同期 | 管理者が決める全員の既定値と強制反映 |
| レコード | 利用者ごとに1件（`login_name` で特定） | アプリ全体で1件だけ |
| フィールド | `login_name`（1行・重複禁止）、`settings_json`（複数行） | `settings_json`、`auth_json`（いずれも複数行） |
| 権限 | レコードは「作成者のみ」閲覧・編集・削除できる。全員にレコード追加を許可 | Everyone は閲覧のみ。管理者だけ編集できる。`auth_json` は管理者だけが閲覧できる |
| 書き込む人 | 各利用者（自分の分だけ） | 管理者だけ |
| 必須かどうか | 任意。プレースホルダーのままなら同期は無効で、端末ごとの保存になる | 任意。プレースホルダーのままなら全体設定と管理者設定は無効で、JS 内の既定値で動く |
| 統合後の扱い | **運用中のため残す**。`portal-navigation.js` でも、バックアップの旧 `portal-shortcut.js` でも同じデータを読む（ロールバックしても設定は失われない） | `portal-navigation.js` だけが使う |

2つのアプリは**兼用しません**。個人設定アプリの作り方の詳細は、[`テンプレートフォルダ/README.md`](テンプレートフォルダ/README.md) の「端末間同期」節を参照してください。

### 全体設定アプリの作り方

1. kintone でアプリを新規作成します（個人設定アプリとは別のアプリ）。
2. フィールドを2つ作ります。
   - `settings_json`: 文字列（複数行）、フィールドコード `settings_json`
   - `auth_json`: 文字列（複数行）、フィールドコード `auth_json`
3. **アプリのアクセス権:** 「Everyone」は閲覧のみ。管理者の組織／グループに、レコードの追加・編集・削除とアプリ管理を与えます。
4. **レコードのアクセス権:** 既定のままにします。
5. **フィールドのアクセス権:** `auth_json` は管理者の組織／グループだけが閲覧・編集でき、Everyone には権限を与えません。`settings_json` は Everyone が閲覧、管理者が編集できるようにします。
6. **最初のレコード:** 管理者が kintone の画面からレコードを1件作ります。2つのフィールドは空で構いません（初回の保存時に、現行の既定値とパスワードが入ります）。レコードは**常に1件だけ**にしてください（ID が一番小さいものを使います）。このレコードは**削除して作り直さないでください**。作り直すと改訂番号（`settingsRev`）が小さい値から始まり直し、個人設定の強制反映が効かないことがあるため、編集して使い続けてください。
7. 作ったアプリの ID を、`portal-navigation.js` の `GLOBAL_SETTINGS_APP_ID` に書きます。プレースホルダー（`your-global-settings-app-id`）のままなら、全体設定と管理者設定は無効になり、JS 内の既定値で従来どおり動きます（リモート API も呼びません）。
8. 端末間同期を使う場合は、従来どおり個人設定アプリを作り `SETTINGS_APP_ID` を書き換えます（[`テンプレートフォルダ/README.md`](テンプレートフォルダ/README.md) を参照）。

### 管理者設定の使い方

1. ポータルの ⚙️ を開きます。全体設定レコードを編集できる人にだけ「🔒 管理者設定」が表示されます。
2. パスワードを入力します（初回はパスワードの設定。8文字以上）。5回続けて間違えると5分間入力できません。認証は30分有効です。
3. 4つのタブで編集します: 「ショートカット既定」「デザイン既定」「反映方法」「パスワード」。
   - 「ショートカット既定」では、アプリを持たないスペースも既存の登録分は名前を解決して表示します。アプリを持たないスペースは「一覧に無いスペースを追加」欄に URL か ID を貼り付けると候補に追加できます（存在しない、または閲覧権限がない場合は赤字で表示します）。
4. 「保存して全体に反映」→ 確認ダイアログ →「保存する」。保存は kintone の revision を指定して行います。
5. 他の管理者が先に保存していた場合は、赤いバナーが出て保存されません。「最新を読み込む」で最新の内容を読み込んでから、もう一度編集してください。
6. 終わったら「🔒 ロックして閉じる」で認証状態を解除できます。

### セキュリティ上の注意

- 管理者パスワードは、ブラウザの中で照合する**補助的な鍵**です。開発者ツールを使えば、画面側の照合やロックは回避できます。**本当の防御は、全体設定アプリのアプリ権限・フィールド権限（kintone 側）**です。
- 管理者から外すときは、全体設定アプリの権限から外すだけで入れなくなります（パスワードを変える必要はありません）。
- パスワードは PBKDF2-SHA256（100,000 回、ソルト付き）のハッシュとして `auth_json` に保存します。`auth_json` は管理者だけが閲覧できるフィールド権限にしてください。
- パスワードを忘れたときは、全体設定アプリで `auth_json` を空にすると、初回設定からやり直せます。

### 個人設定アプリへの影響

- 個人ショートカットの JSON に `baseRev` が増えます。旧データ（`baseRev` が無いもの）は 0 として扱います。
- 旧ファイルが読んでも `baseRev` は未知のキーとして無視されるため、互換性は保たれます。

### localStorage / sessionStorage のキー一覧

| キー | 保存先 | 内容 |
|---|---|---|
| `kintone_portal_shortcuts_<userId>` | localStorage | 個人ショートカット（`baseRev` を追記） |
| `kintone_portal_shortcuts_mode_<userId>` | localStorage | 保存先モード（`app` / `local`） |
| `kintone_portal_theme_idx` / `kintone_portal_shape_idx` | localStorage | 🎨🔲 の選択（従来どおり） |
| `kintone_portal_home_theme_idx` | localStorage | 🏠 の選択（ホームボタンの色） |
| `kintone_portal_design_rev` | localStorage | 🎨🔲🏠 を最後に変えた時点の `settingsRev` |
| `kintone_portal_global_settings_v1` | localStorage | 全体設定のキャッシュ（最長10分） |
| `kintone_portal_admin_lock_<userId>` | localStorage | パスワード失敗のロック状態 |
| `kintone_portal_admin_auth_<userId>` | sessionStorage | 管理者認証の有効期限 |
| `kintone_portal_admin_acl_<userId>` | sessionStorage | 管理者権限の判定結果（10分） |

フォント側のキー（`kintone-custom-font-size` など）には触れません。

### 切り替え手順

1. 「JavaScript / CSS でカスタマイズ」で、旧 `portal-shortcut.js`（PC・スマートフォン）と旧 `mobile-home-button.js`（スマートフォン）の**登録を外します**。
2. `portal-navigation.js` を **PC 用とスマートフォン用の両方**に登録します。どちらでも `font-size-changer.js` より上（先に読まれる位置）に置きます。
3. 保存して確認します。

旧ファイルを同時に登録すると、先に読まれた側だけが描画します。統合ファイルが後に読まれた場合は、コンソールに警告（`旧 portal-shortcut.js と同時に登録されています`）が出ます。

### 戻す手順（ロールバック）

`portal-navigation.js` の登録を外し、旧2ファイルを元の欄に**登録し直します**。個人設定アプリのデータはそのまま使えます（`baseRev` は無視されます）。

## 🚀 ショートカットボタン（`テンプレートフォルダ/ショートカットボタン/portal-shortcut.js`）

> バックアップ（従来版）。現行は 🧭 ポータルナビ。以下はロールバック時の参照用です。

Kintone ポータル画面の上部に、よく使うアプリへのショートカットボタンを配置します。

- **アプリショートカットボタン**
  - `appList` 配列（`portal-shortcut.js` 内）は**未設定時に表示される既定値**です。配置したいアプリのIDと表示名を列挙します。プレースホルダー（`your-app-id-1` 等）を実際のアプリIDに書き換えて利用してください。詳細は [`テンプレートフォルダ/README.md`](テンプレートフォルダ/README.md) を参照。
  - ボタンの遷移先は各アプリの `/k/{アプリID}/` です。行数は自由に増減できます（既定値としては4〜6個程度が目安）。
- **カラーテーマ変更（🎨）・形状変更（🔲）**
  - ボタンのグラデーション配色（navy / green / purple / standard）と角丸形状（capsule / rounded）を切り替えできます。
  - 選択値はブラウザの `localStorage`（`kintone_portal_theme_idx` / `kintone_portal_shape_idx`）に個別保存されます。
- **個人カスタマイズ（⚙️）**
  - 🎨・🔲 の隣の ⚙️ ボタンから、ショートカットの**遷移先（アプリ／スペース）・表示名・並び順・個数（4〜6個）**をユーザー本人が編集できるモーダルを開きます。各行には「登録する遷移先」「ボタンに表示する名前」のラベルが常時表示され、カード状にまとまった行に番号が振られます。
  - 遷移先は名前順に並んだ選択肢（プルダウン）から選びます。「アプリ」「スペース」の2つの `<optgroup>` にまとまって表示され、IDは画面に表示されません。表示名は既定で選択した名称に追従し、任意に上書きできます（未入力の場合は選択した名称がそのまま表示されます）。プレビューでは、スペースを選んだ行の先頭にのみ 📁 が付きます。
  - スペースの候補は、既に配置されているアプリの所属スペースから自動的に集めて一覧に出します。**アプリを1つも持たないスペース**は一覧に出ないため、モーダル内の「一覧に無いスペースを追加」欄にスペースのURL（例: `https://xxx.cybozu.com/k/#/space/16`）または数字のスペースIDを貼り付けることで、候補に追加できます。
  - 編集中の内容は**「完成イメージ」としてモーダル内にプレビュー表示**され、保存前にポータル上での見え方を確認できます。
  - モーダルの配色は**🎨 で選択中のテーマカラーに連動**します（ヘッダー・保存ボタン・フォーカス色などがテーマに追従）。
  - 設定はブラウザの `localStorage`（`kintone_portal_shortcuts_<ログインユーザーID>`）に**ログインユーザー単位**でキャッシュされ、常にこのキャッシュから即時に描画されます。未設定・保存データが壊れている・件数が範囲外などの場合は、常に既定の `appList` へ自動的にフォールバックし、ポータルが空になることはありません。「既定に戻す」ボタンで保存内容を削除し、いつでも既定値に戻せます。
  - アプリ一覧の取得（`/k/v1/apps.json`）は ⚙️ モーダルを開いたときのみ実行され、通常のポータル表示時には行われません。
- **端末間同期（任意・設定アプリ方式）**
  - 別途用意した「設定アプリ」を使うことで、⚙️ モーダルの「この設定の保存先」ラジオから**「すべての端末で共有する（既定）」／「この端末だけに保存する」**をユーザー自身が選べます。共有を選んだ場合、保存内容は設定アプリのレコード（自分の分のみ）に保存され、他端末・他ブラウザでも同じ内容が反映されます。
  - 保存先の選択自体は端末ごとの localStorage（キー: `kintone_portal_shortcuts_mode_<ログインユーザーID>`）に保存されます。
  - ポータル描画は常に localStorage キャッシュから即時に行われ、共有モードのときだけ描画直後に非同期でリモート設定と照合し、内容が異なる場合のみキャッシュを更新して再描画します（初期表示速度への影響なし）。取得失敗時やレコードなしの場合は何もせず、キャッシュ表示を維持します。
  - 共有モードでの保存は、設定アプリへの保存が成功してからローカルキャッシュを更新します。失敗した場合はモーダルを閉じずにエラーを表示します。共有モードでの「既定に戻す」は、設定アプリのレコードを削除できてからローカルキャッシュを削除します（すべての端末の設定が既定に戻ります）。
  - `portal-navigation.js`（およびバックアップの `portal-shortcut.js`）内の `SETTINGS_APP_ID` がプレースホルダー（`your-settings-app-id`）のままの場合、同期機能自体が無効になり、保存先ラジオも表示されず、リモートAPIも一切呼ばれません。従来どおり端末（ブラウザ）ごとの保存のみで動作します。設定アプリの作り方・書き換え方法は [`テンプレートフォルダ/README.md`](テンプレートフォルダ/README.md) を参照してください。

### 🧩 共有コーディネーター `window.PortalCustomize`

ポータル上部のコンテナと「マウントスロット」を提供する軽量な共有ロジックです。各機能ファイルは「自分のボタンを所定スロットに挿す」ことだけに責務を限定でき、**読み込み順に依存せず**に協調動作します。

- **冪等初期化**: コンテナは一度だけ生成されます（重複防止 ID: `my-custom-app-container`）。
- **提供スロット**:
  - スロット1: ショートカットボタン群 … `addShortcutItem(el)`
  - スロット2: 色 / 形ボタン … `addConfigItem(el)`
  - スロット3: フォントボタン群（`configContainer` 右寄せ）… 本リポジトリでは未使用。将来フォント機能を分割した際に `getConfigContainer()` を取得してマウントする想定です。

> フォント設定（`localStorage` キー・`kintone-font-size-changed` イベント）はフォント側の所有物であり、`portal-shortcut.js` からは一切操作しません。

## 🔠 フォントサイズ変更（`テンプレートフォルダ/フォントサイズ/font-size-changer.js`）

画面右下に常駐する**格納式セグメントUI**から、文字サイズを「小（14px）/ 中（18px）/ 大（24px）」で切り替えます。

- **格納 / 展開**: 格納時は「**文字**」ボタン、クリックで小中大セグメントが展開します（展開レイアウトは `[小 中 大]`（px併記・スライドインジケータ）＋ 右に「文字」ボタン）。
- **対象画面共通**: ポータル・レコード一覧/詳細・レポート・スペースの各画面（PC / モバイル）で同じUI・操作を提供します。
- **状態の永続化**: 開閉状態は `localStorage`（`kintone-font-ui-collapsed`、既定は格納）、選択サイズは `localStorage`（`kintone-custom-font-size`）に保存し、再読み込み後も維持します。
- **スタイル注入**: ウィジェットの見た目は重複防止ID付きの `<style>`（`kintone-font-ui-style`）で1度だけ注入します。
- **Allowlist方式のCSS注入**: レコード値・コメント・ポップアップ等の「読むテキスト」エリアのみを対象とし、ヘッダー・サイドバー等のシステムUIは除外して表示崩れを防ぎます。スペース・アプリ一覧・通知カードは対象外です。
- **自己完結**: ショートカット機能や共有コーディネーター `window.PortalCustomize` には依存しません。

> 設計上、ポータル上部にインラインの小中大ボタンは持ちません（右下のウィジェットに一本化）。

## 🗂 ポータルのスペース一覧 表示制御（`テンプレートフォルダ/スペース設定/space-visibility-filter.js`）

ポータルの「スペース」ポートレットから、**ホワイトリストに登録していない公開スペースを非表示**にします。マンションのコミュニティ用スペースを**ハブスペース経由**でアクセスさせるための UI 整理です。

- **ホワイトリスト方式**: `VISIBLE_SPACE_IDS`（既定 `['2', '3', '6', '16']`）に無い公開スペースは自動的に隠れます。新しくコミュニティ用スペースを作っても設定変更は不要です。
- **鍵マーク付き（非公開）スペースは対象外**: Kintone 標準で参加者にしか表示されないため、そのまま残します。
- **参加済みなら表示**: ホワイトリスト外でも、すでに参加しているスペースは表示されます。全ユーザーに同じルールを適用し、管理者等の特別扱いはありません。
- **PC・モバイル共通**: 1 ファイルで両方に対応し、同じファイルを PC 用・スマートフォン用の両方に登録します。
- **フェイルセーフ**: 判定に失敗した場合は「何も隠さない」＝ Kintone 標準の表示に戻ります。スペース一覧が隠れたままになることはありません。

> **セキュリティ機能ではありません。** ポータルの見た目から消えるだけで、URL 直打ち・全体検索からは引き続きアクセスできます（スペースは公開のままで、誰でも自由に参加できます）。

設定方法・鍵マーク判定が壊れた場合の復旧手順は [`テンプレートフォルダ/スペース設定/space-visibility-filter-README.md`](テンプレートフォルダ/スペース設定/space-visibility-filter-README.md) を参照してください。

## 🚪 スペースの参加・退会ボタン（`テンプレートフォルダ/スペース設定/space-join-button.js`）

スペースのトップ画面に「参加する」「退会する」ボタンを表示します。Kintone 標準では参加・退会が右上の「…」メニューの中にしかなく気づけないため、**参加したつもりで参加できていない**という状態が起きます。これを1クリックに集約します。

- **参加状況に応じた3状態**: 非メンバーには「参加する」、自分で参加した明示的メンバーには「退会する」を表示します。
- **暗黙的メンバーにはボタンを出しません**: `everyone` などの組織・グループ経由でメンバーになっている場合、Kintone 自身が参加・退会の手段を持たないため（個人単位で抜けられない）、押しても失敗するボタンを表示しません。
- **自分1人だけを操作**: Kintone 本体と同じ内部エンドポイントを使い、自分の参加・退会だけを行います。メンバー一覧を全件置換する REST API は、同時更新で他の人の変更を消す危険があるため使いません。
- **PC・モバイル共通**: モバイル版 Kintone には参加・退会 UI が標準で存在しないため、両方に同じ方式で提供します。
- **フェイルセーフ**: 状態を判定できない場合はボタンを表示しません。失敗しても Kintone 標準の画面はそのまま使えます。

> コミュニティ用スペースには **`everyone` をメンバーに入れないでください**。入れると全員が暗黙的メンバーになり、参加ボタンが出ず退会もできなくなります。

詳細は [`テンプレートフォルダ/スペース設定/space-join-button-README.md`](テンプレートフォルダ/スペース設定/space-join-button-README.md) を参照してください。

## ⚠️ 運用・保守上の注意

- **（旧ファイルをロールバックで使う場合）既存ファイルとの同時適用は避けてください。**
  バックアップの `portal-shortcut.js` は重複防止 ID に既存ファイルと同一の `my-custom-app-container` を使用します。旧来のポータルカスタマイズファイルと**同時に適用すると、先に実行された側のみが描画され、ショートカットの二重表示や色/形ボタンの欠落が発生**します。旧ファイルを置き換えてから適用してください。
- **`portal-navigation.js` と旧2ファイル（`portal-shortcut.js`・`mobile-home-button.js`）を同時に適用しないでください。** 先に読まれた側だけが描画し、後から読まれた統合ファイルはコンソールに警告を出します。切り替え時は旧ファイルの登録を外してください。
- **DOM 操作に関する注意**: Kintone 本体のアップデートにより DOM 構造が変わると、動作に影響が出る可能性があります。
- 本リポジトリには API キー等の機微情報は含めません。
