# スペースの参加・退会ボタン（`space-join-button.js`）

スペースのトップ画面に「参加する」「退会する」ボタンを表示するカスタマイズです。PC・モバイルの両方に対応します。

Kintone 標準では、参加・退会は**右上の「…」オプションメニューを開かないと現れません**。メニューを開くまで存在に気づけないため、「スペースを見たので参加したつもりだったが、実際には参加できていなかった」という状態が起きます。このカスタマイズは、その操作をトップ画面のボタン1つに集約します。

---

## ボタンの3状態

自分の参加状況に応じて表示が変わります。

| 自分の状態 | ボタン | 動作 |
|---|---|---|
| 非メンバー | **「＋ このスペースに参加する」**（青） | 押すと参加し、画面を再読み込み |
| 明示的メンバー | **「このスペースを退会する」**（グレー） | 確認ダイアログ後に退会し、画面を再読み込み |
| **暗黙的メンバー** | **表示しない** | 後述 |
| 状態を判定できない | **表示しない** | 安全側に倒す |

### 「暗黙的メンバー」とは（＝ everyone 参加スペースが対象外になる理由）

Kintone のメンバーには2種類あります。

- **明示的メンバー**（`isImplicit: false`）— 個人として直接追加された、または自分で「参加」した状態
- **暗黙的メンバー**（`isImplicit: true`）— 所属する**組織やグループ（`everyone` を含む）がスペースのメンバーになっている**ため、間接的にメンバー扱いになっている状態

暗黙的メンバーには、**Kintone 自身も参加・退会の手段を提供していません**（標準のオプションメニューにも項目が出ません）。個人が抜けるという概念が存在しないためです。押しても必ず失敗するボタンを出さないよう、この状態ではボタンを表示しません。

`everyone` グループがメンバーになっているスペースは全ユーザーが暗黙的メンバーになるため、結果として**ボタンは表示されません**。

> [!TIP]
> 今後コミュニティ用スペースを作る際は、**`everyone` をメンバーに入れない**でください。入れてしまうと全員が最初から暗黙的メンバーになり、参加ボタンが出ないうえ、個々の住民が退会することもできなくなります。

## 設定

`space-join-button.js` 冒頭の `CONFIG` だけを編集します。

| 設定項目 | 既定値 | 説明 |
|----------|--------|------|
| `EXCLUDE_SPACE_IDS` | `[]` | ボタンを表示しないスペース ID。既定では全スペースに表示します |
| `SHOW_LEAVE_BUTTON` | `true` | `false` にすると参加ボタンのみになり、退会ボタンを出しません |
| `CONFIRM_ON_LEAVE` | `true` | 退会時に確認ダイアログを出すか |
| `JOIN_LABEL` | `'＋ このスペースに参加する'` | 参加ボタンのラベル |
| `LEAVE_LABEL` | `'このスペースを退会する'` | 退会ボタンのラベル |
| `DEBUG` | `false` | `true` にすると判定結果をブラウザのコンソールに出力します |

## 導入手順

1. cybozu.com 共通管理 → **カスタマイズ／サービス連携** → **JavaScript / CSS でカスタマイズ**
2. **PC 用**の「JavaScript ファイル」に `space-join-button.js` をアップロード
3. **モバイル用**の「JavaScript ファイル」にも**同じファイル**をアップロード
4. 保存後、スペースを開いて表示を確認

PC・モバイルの両方の処理が 1 ファイルに入っているため、登録するファイルは 1 つだけです。

> [`space-visibility-filter.js`](space-visibility-filter.js)（ポータルのスペース一覧 表示制御）と組み合わせて使うことを想定しています。ハブスペース経由でコミュニティスペースを開き、このボタンで参加すると、参加済みのスペースとしてポータルにも表示されるようになります。

## 仕組み

### 参加状態の判定

`GET /k/v1/space/members.json` で自分がメンバー一覧に含まれるかを確認し、含まれる場合は `isImplicit` で明示的／暗黙的を区別します。

### 参加・退会の実行

Kintone 本体が使っている内部エンドポイントを呼び出します。

```text
POST /k/api/space/join.json   { spaceId, __REQUEST_TOKEN__ }
POST /k/api/space/leave.json  { spaceId, __REQUEST_TOKEN__ }
```

CSRF 対策のトークンは `kintone.getRequestToken()` から取得します。

**REST API の `PUT /k/v1/space/members.json` は使いません。** この API は「メンバー一覧の全件置換」であり、以下の理由で住民が押すボタンには不適だからです。

- スペース管理者権限が必要で、一般の住民は実行できない
- 全件を読んで書き戻すため、**同時に他の人が参加・退会するとその変更が消える**（数十〜百名規模のスペースでは実害が大きい）

上記の内部エンドポイントは**自分1人の参加・退会だけ**を行うため、この危険がありません。

### PC とモバイルで同じ方式を使う理由

**モバイル版の Kintone には、参加・退会の UI がそもそも存在しません**（実機で確認済み。メンバー・非メンバーどちらでもボトムシートには「お気に入り」しか出ません）。そのため「標準メニューの項目を自動クリックする」方式はモバイルで成立しません。PC も同じエンドポイントを直接呼ぶ方式に揃えることで、PC・モバイルで挙動が一致し、メニュー項目の日本語テキストへの依存も避けられます。

## トラブルシューティング

### ボタンが表示されない

以下のいずれかに該当していないか確認してください。`DEBUG: true` にすると、コンソールの `[space-join-button]` のログで判定結果が分かります。

- そのスペースが `everyone` などの組織・グループ経由でメンバーになっている（＝暗黙的メンバー。仕様通り表示しません）
- `EXCLUDE_SPACE_IDS` に含めている
- 明示的メンバーで、`SHOW_LEAVE_BUTTON` を `false` にしている
- メンバー一覧の取得に失敗している（権限エラー等。安全側に倒してボタンを出しません）

### 参加・退会できない

エラーダイアログが出た場合、通信エラーか Kintone 側で操作が拒否された可能性があります。標準のオプションメニュー（右上の「…」）からも同じ操作ができるので、そちらでもお試しください。

### 画面が壊れた

本カスタマイズは**失敗したら何も表示しない**設計です。処理中にエラーが起きてもボタンが出ないだけで、Kintone 標準の画面はそのまま使えます。

---

## 保守のポイント

Kintone の DOM 構造に依存する箇所は、ファイル内の `TARGETS` に集約しています（2026-08 時点の実機で確認）。

| | PC | モバイル |
|---|---|---|
| ボタンの差し込み先 | `div.gaia-argoui-space-spacelayout-toolbar`（内側に追加） | `div.gaia-mobile-v2-space-spaceheader`（直後に挿入） |
| URL 形式 | `/k/#/space/14` | `/k/m/space/14` |
| イベント | `space.portal.show` | `mobile.space.portal.show` |

- PC の差し込み先にカバー画像（`-cover`）は**使えません**。高さが固定されており、ボタンがはみ出して下のウィジェットに重なります。カバー直下の空のツールバー領域に入れると、コンテンツを押し下げる形で収まります
- 参加・退会のエンドポイントは **HTTP 200 のまま本文の `success` で成否を返します**。ステータスコードだけで成功と判断しないでください
- ボタンは要素 ID `space-join-button` で一意にし、描画前に必ず既存のものを削除しています（画面遷移での二重表示を防ぐため）
- 押下中はボタンを `disabled` にし、連打による多重リクエストを防いでいます

---

## 公開リポジトリでの取り扱い

このファイルには**スペース ID などの固有情報は含まれません**（`EXCLUDE_SPACE_IDS` は既定で空）。サブドメインや認証情報も含まないため、そのまま利用できます。
